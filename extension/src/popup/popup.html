    Sync (dev)

    Round-trips the sealed container through a local dev sigild op-log over plain HTTP. The server only ever sees opaque bytes. If that sigild has device auth on, enroll below and every request is signed by this device’s Ed25519 key (computed in the wasm).

    Device identity

    Not enrolled — sync requests are unauthenticated.

    Codes are computed from this device’s system clock. Once it has drifted more than half a TOTP step, codes are likely to be rejected even though the secret is perfectly correct, and the further it drifts the more certain that becomes. Some verifiers accept a code from one step either side, so a small drift may still get through, but you cannot count on it. This compares against the server’s clock; it never changes the one codes come from.

    Sharing (dev)

    Share this vault with another enrolled device. A shared vault is sealed under a random 32-byte vault key, and that key is wrapped to the recipient’s hybrid public key (X25519 + ML-KEM-768). Your password is never shared or wrapped — the server relays an opaque envelope it cannot read. Uses the Server URL and Vault id from Sync above.

    Enroll this browser as a device first (Sync above).

    Draws a fresh vault key, re-seals this vault, re-wraps it to those devices and deletes every other envelope. Protects future content only — a device that already unwrapped the old key keeps what it copied.

    Recovery kit (dev)

    A recovery kit is an ordinary member device of your account whose keys come from paper. The server gains no concept of “recovery”: it sees one more device, one more published public key and one more opaque envelope per covered vault. It is the only thing that gets your vaults back if every device is lost, and it cannot be created after that happens.

    This browser holds no vault keys yet, so a kit generated now would cover nothing — and a kit that covers nothing recovers nothing. Convert this vault to a shared vault first (Sharing above).
