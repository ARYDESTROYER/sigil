sigil-wasm

Seals and opens a record entirely in your browser via the sigil-core record API (Argon2id → XChaCha20-Poly1305), compiled to WebAssembly. The Argon2id salt and the AEAD nonce are generated here in JavaScript with crypto.getRandomValues and passed into the wasm — the module has no randomness of its own.

Hybrid PUBLIC-KEY encryption (SIGILhyb)

    

      The no-password, public-key path. A device generates a HYBRID IDENTITY
      (an X25519 key pair + an ML-KEM-768 keypair-seed); senders encrypt TO its
      shareable .pub and only the holder of the secret identity can
      decrypt. This composes sigil-core's hybrid primitives
      (X25519 + ML-KEM-768 → shared secret → XChaCha20-Poly1305). The secret,
      the ephemeral X25519 secret, the ML-KEM coin, and the nonce are ALL
      generated here in JS with crypto.getRandomValues. The
      container is byte-compatible with sigil hybrid-seal /
      sigil hybrid-open.
      CUSTOM KEM-then-AEAD, NOT RFC 9180 HPKE; the system is NOT
      post-quantum secure. UNAUDITED — do not protect real secrets.
    


    

      
      
    

    
    

    

      The matching SECRET identity is held in memory for this page only (it is
      NOT downloaded). Regenerate to get a fresh pair.
    


    
    

    

      
      
    

    

      Seals to the recipient .pub you load, or — if none is loaded —
      to your OWN identity above, so you can immediately open it below (a
      self-round-trip). The container is a SIGILhyb file; open it on
      the command line with
      sigil hybrid-open --key your.key --in note.hyb --out note.txt.
    


    

      
    

    
    

    
    


    


    
Sync over the dev sigild op-log (SIGILcli)

    

      DEV / LOCALHOST / PLAIN HTTP / NO AUTH. Needs a local sigild started with
      SIGILD_ENABLE_DEV_OPS=1 on loopback (e.g.
      SIGILD_ADDR=127.0.0.1:8080 SIGILD_ENABLE_DEV_OPS=1 ./sigild).
      Do NOT point this at a remote host.
    

    

      Closes the E2EE sync loop from the browser: Seal + Push
      seals the Plaintext above into a SIGILcli container and
      POSTs the OPAQUE bytes to the op-log; Pull + Open drains the
      vault, opens the LATEST container with the password above, and shows the
      recovered plaintext. The server is zero-knowledge — it
      stores and returns the exact sealed bytes and does NO crypto; confidentiality
      is the browser sealing BEFORE push. This interoperates with the
      sigil push / sigil pull CLI through the same vault.
    


    
    

    
    

    

      
      
    


    
    


    
    


    


    
TOTP authenticator vault (SIGILcli)

    

      DEV / UNAUDITED — do NOT enter a real 2FA secret. This is a demonstration
      of the RFC 6238 TOTP primitive, not a hardened authenticator.
    

    

      Add a base32 TOTP secret and this page keeps an in-memory vault, showing the
      LIVE code for each entry (refreshed every second, with a countdown to the
      next period). The time comes from your browser clock
      (Date.now()/1000) — sigil-core reads no clock, so
      the wasm TOTP takes the time as an argument. Seal + Push vault
      seals the whole vault into a SIGILcli container (the SAME format
      the sigil totp CLI uses) and pushes the OPAQUE bytes to the dev
      op-log above; Pull + Open vault pulls it back and decrypts it
      here. The vault is cross-compatible with
      sigil totp add/list/code at the command line (same password).
