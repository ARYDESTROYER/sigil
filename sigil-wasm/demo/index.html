sigil-wasm

Seals and opens a record entirely in your browser via the sigil-core record API (Argon2id → XChaCha20-Poly1305), compiled to WebAssembly. The Argon2id salt and the AEAD nonce are generated here in JavaScript with crypto.getRandomValues and passed into the wasm — the module has no randomness of its own.

Interop with the sigil CLI

    

      This path uses the CLI-compatible SIGILcli container format
      (self-describing: magic, version, Argon2 params, salt, then the envelope,
      with AAD sigil-cli/1). Download seals the
      plaintext above and saves a .sigil file you can open on the
      command line with
      SIGIL_PASSWORD='…' sigil open --in note.sigil --out note.txt.
      Upload reads a container — one from this demo or
      one written by sigil seal — and opens it here. Use the same
      password in both places.
    


    

      
      
    


    
    


    
    


    


    
Hybrid PUBLIC-KEY encryption (SIGILhyb)

    

      The no-password, public-key path. A device generates a HYBRID IDENTITY
      (an X25519 key pair + an ML-KEM-768 keypair-seed); senders encrypt TO its
      shareable .pub and only the holder of the secret identity can
      decrypt. This composes sigil-core's hybrid primitives
      (X25519 + ML-KEM-768 → shared secret → XChaCha20-Poly1305). The secret,
      the ephemeral X25519 secret, the ML-KEM coin, and the nonce are ALL
      generated here in JS with crypto.getRandomValues. The
      container is byte-compatible with sigil hybrid-seal /
      sigil hybrid-open.
      CUSTOM KEM-then-AEAD, NOT RFC 9180 HPKE; the system is NOT
      post-quantum secure. UNAUDITED — do not protect real secrets.
